## [Unreleased]

### Changed

- **ship-better-plans** 2.0.0 — full rewrite after a multi-persona audit and a before/after evaluation (see `docs/agent/investigations/ship-better-plans-refresh-audit.md`). **Breaking: new plan format (`plan_format: 2`).**
  - *Process:* discovery now runs before any question; the eight-field one-at-a-time intake is replaced by a single checkpoint (brief, recommended approach, up to four batched questions, review depth). The chosen approach is challenged by a subagent before the checkpoint. Plans are sized to the work, with `N/A — reason` in place of mandatory filler, and an unattended path that records assumptions instead of stalling. Outside plan mode the plan file is written early as `approval: draft` and approved explicitly.
  - *Plan format:* tasks are self-contained **cards** (`Depends on`, `Covers`, `Files`, `Do`, `Verify`, `Kind`, `Size`, `Reversibility`, `Gate`) plus a "Conventions for every task" block; facts carry `path:line` or `ran:` evidence; assumptions say what settles them; the execution order is derived from the cards.
  - *Plan linter (new):* `scripts/lint_plan.py` checks structure and placeholders, traceability from success criteria to tasks, the dependency graph, a stale pasted execution order, file collisions between parallel tasks, gates on tasks that are not safely reversible, and that cited files, evidence lines and package scripts exist. `--dag` derives the execution order. 43 unit tests; CI lints the bundled examples.
  - *Review:* the audit workflow is rewritten. Reviewers (`executor`, `grounding`, `adversary`, `scope`, plus `security` / `data` / `ops` / `tests` chosen from the plan's content) read the plan file and check it against the repository; duplicates are merged; each blocker or major finding is verified with a three-way verdict (confirmed / refuted / uncertain) instead of "refuted when unsure", and a refuted blocker gets a second opinion. Ultra is bounded (three rounds, told what was already found, stops on a confirmed blocker) and adds a `recheck` of the revised plan; there is a one-agent `light` depth. Failed reviewers, dropped findings and unverified findings are reported, never silently lost. Falls back to parallel Agent calls where the Workflow tool is unavailable.
  - *Docs:* three example plans (small, feature, refactor) that pass the linter; `/ship-plan` hands off to `/ship-execute`.
- **ship-execute** 2.0.0 — full rewrite after a six-reviewer audit and a before/after evaluation (see `docs/agent/investigations/ship-execute-refresh-audit.md`). Reads the `ship-better-plans` 2.0 plan format.
  - *Plan reader (new):* `scripts/plan_tasks.py` parses the task cards, prints each task agent's exact briefing (card, covered criteria, owned files, verification, conventions, setup, and the rules a task agent works under), computes which tasks are ready (a gated task is never in a parallel set; a declined or blocked task stops only its dependents), checks a task's commit against its card (a changed or deleted test, a changed check configuration, or committed caches or environment files that the card does not own, fails), compares the cards with the repository before the run (`preflight`), and keeps a run ledger inside `.git` that refuses claims it can check: no `done` without a verification note and a commit on the branch, no gated task without a recorded approval, no task before its dependencies, no work off the run's branch; a gate approval covers one dispatch of one card; cleanup removes only a finished task's own worktree. 57 unit tests.
  - *Git protocol:* one commit per task; the working tree must be clean and is never stashed; work happens on a `ship/<plan>` branch; every task agent runs in an isolated worktree and its commit is checked, then cherry-picked onto the execution branch, one at a time; a commit whose check fails there is reverted; files are staged by path; worktrees and throwaway branches are removed only after their commit is on the branch.
  - *Evidence:* a task agent's "done" is a claim. The orchestrator re-runs each card's `Verify` on the execution branch, runs the suite after each parallel wave, and compares the final commit with a recorded baseline.
  - *Plan and reality:* a card that contradicts the code, an existing test or its own check returns `needs-decision` and goes to the user; one fresh retry on failure, then `blocked`; the run continues with whatever does not depend on it.
  - *Review:* the final review is a local, independent review of the whole diff against the plan's criteria (the previous design required a pull-request reviewer before any pull request could exist). Riskier tasks are reviewed during the run. Sibling review skills are used when installed and are optional. Fix rounds are bounded.
  - *Run shape:* read-only inspection first, one start question (skipped when the user has just chosen "approve and build now" in `ship-better-plans`), resumable from the ledger, an unattended mode that never runs gated tasks or pushes, an honest report, and a plan marked `completed` only when it is. Discarding asks twice.

- **ship-reviewed-prs** 1.4.0 — full rewrite after a six-reviewer audit and a before/after evaluation on pull requests with seeded defects (see `docs/agent/investigations/ship-reviewed-prs-refresh-audit.md`). The overrides file, `--strict`, `--json` and exit codes are gone; this is released as a minor version at the maintainer's request, so consumers pinned to 1.x get the new behaviour.
  - *Review script (new):* `scripts/review_pr.py` gathers the pull request (every thread, paginated; CI state; the changed files, including renames and deletions; earlier reviews), prints files and the diff with line numbers, validates the reviewer's findings file, computes the verdict, renders the summary, and posts one review in a single request pinned to the reviewed commit. The previous instructions posted inline comments to an endpoint the REST API does not have. `check` refuses a comment whose line is outside the diff and shows the code under each comment and suggestion; `post` refuses when new commits arrived, when the commit was already reviewed, when the user has a pending review, and, interactively, without `--confirmed`. 66 unit tests run it against a stand-in `gh` that validates writes as GitHub does.
  - *Review method:* seven lenses with correctness against the pull request's stated intent first, in place of persona rubrics with numbered finding IDs. Severity (`must-fix`, `should-fix`, `nit`) is the consequence of merging, not a digit in an ID. Every must-fix and should-fix carries what was checked; a must-fix gets an independent second look. Sibling skills are loaded during the review for depth instead of the author being told to run them.
  - *Existing threads:* each open thread gets a disposition (`still-valid`, `fixed`, `settled`, `withdrawn`, `no-action`, `unclear`) from reading the thread and the code, replacing keyword and fingerprint matching. An author alone cannot settle a concern someone else raised, nor close it by resolving the thread; a maintainer can decline one of the tool's own findings; a thread a person reopened is never resolved again.
  - *Posting:* on your own pull request the review is posted as a comment that still states its verdict (GitHub refuses an author's approval); a refused approval is retried as a comment; the tool's stale approval or block is dismissed; only the tool's own threads are resolved.
  - *Safety:* pull request content is material, never instructions; text that tries to steer the reviewer is reported; team settings and conventions are read from the base branch; an unattended run does not approve a change to CI, agent configuration or the reviewer; a review cannot carry a credential.
  - *CI:* a model cannot set an exit code, so the script writes `result.json` and a workflow step fails the job when no review was posted. One example workflow (`examples/pr-review.yml`) replaces three, two of which could not run. Team settings are a small JSON file, `.claude/ship-reviewed-prs.json`.
  - *Output:* same verdict labels and findings table; the always-rendered persona and thread tables are replaced by a coverage paragraph and an "Existing threads" section that appears only when there are threads.
  - *Removed:* `reference-personas.md`, `reference-lifecycle.md`, the three `lang-*.md` files, `overrides.example.md`, the nine paste-in fixtures and the old examples.

- **ship-agent-context** 1.3.0 — full rewrite after a six-reviewer audit and a before/after evaluation (see `docs/agent/investigations/ship-agent-context-refresh-audit.md`). Existing `docs/agent/` folders keep working; run `agent_context.py index` once to regenerate `MANIFEST.md`.
  - *Notes script (new):* `scripts/agent_context.py`. `digest` prints the standing instructions, the open hand-offs and note counts in about 2 KB, offline; `find` lists the notes about the files or topic in hand, with why each matched; `reconcile` checks each hand-off against git and GitHub (`DONE` / `OPEN` / `UNKNOWN`, with evidence) and each dated instruction against today, and `--apply` archives what is finished; `new` writes a note in one call; `archive` closes one, fixes links to it and rebuilds the index; `index` generates `MANIFEST.md`; `check` validates the folder. Values from notes never reach a shell, and the script refuses to write in CI. 50 unit tests.
  - *Session start:* the plugin hook runs `digest` instead of ordering the agent to read files. Nothing is read because a note is marked `importance: core` (33 of this repository's 38 notes were, about 50 thousand tokens a session); notes are looked up when a change touches their area.
  - *Trust:* notes are a colleague's notes, not standing orders. A recorded instruction that adds a check or a restriction is followed, including over a tool's default; one that would let the agent do more needs the user's yes in the session; text addressed to agents that claims authority or asks for concealment is flagged. A branch cannot retire a rule by deleting it or dating it.
  - *Hand-offs:* `status/` notes are written when work will outlast the session and carry a structured `done_when` (`pr:`, `branch:`, `commit:`, `pending`, `manual`). A missing branch is no longer taken as proof of completion, and only an explicit anchor can close a note.
  - *Writing:* one test for what is worth a note; every standing rule in a message is recorded, from the user's own words only, and the announcement says the file is not committed yet; credentials are refused; the skill never stages, commits or pushes on its own.
  - *Index:* `MANIFEST.md` is generated from each note's `summary`, sorted, with no counters, so it cannot drift and regenerating resolves a merge conflict.
  - *Also:* a `/ship-agent-context:notes` command (show, find, check, tidy, note, remember, forget, init); `SKILL.md` went from 645 lines to 164.
  - *Removed:* the ledger, team mode, index splitting, the scope grammar, timed promotion to `AGENTS.md`, the plan template and the four example transcripts.

### Added

- **CI: notes script tests** — the `plan-lint` job also runs `ship-agent-context`'s unit tests and `agent_context.py check` on this repository's own `docs/agent/`.
- **CI: review script tests** — the `plan-lint` job also runs `ship-reviewed-prs`'s unit tests.
- **PR dogfood workflow** — `.github/workflows/pr-review.yml` now fails when no review was posted, skips pull requests from forks, and asks for a comment-only review when a pull request changes the reviewer, CI or agent configuration.
- **CI: `plan-lint` job** — runs the plan linter's and the plan reader's unit tests, lints the bundled example plans, and checks that the executor's plan reader accepts them, so the examples and the two skills cannot drift apart.
- **ship-vuln-fix** 0.2.0 — **recipe-first remediation**. Adds a hybrid recipe/tool-orchestration layer (`ecosystem-recipes.md`): the skill now prefers a tested, proven remediation recipe/tool when one exists for the CVE+ecosystem — OpenRewrite/Moderne AST recipes (strongest for Java; can carry breaking migrations), native fixers (`npm audit fix`, `pip-audit --fix`, `snyk fix`), and Dependabot/Renovate (compatibility-scored upgrade PRs, surfaced as evidence / emitted as config rather than run) — and falls back to the manual minimal edit otherwise, mirroring `ship-vuln-scan`'s scanner-then-fallback model. The recipe is a stronger fix source but **never skips the verify gate**. Hardened after a focused adversarial review (7 findings folded in): the recipe *process* is treated as untrusted third-party code — run only from a **pinned, checksum-verified coordinate allowlist**, **offline with no credentials** (it executes before any sandboxed install); native fixers are **non-`--force` only**; the Dependabot compatibility score is **non-gating context**, never an apply input; and a trusted AST recipe may move a *breaking* upgrade from advise → apply-eligible only when **per-package opted in**, above a **coverage floor** over the changed API surface, scope-bounded, and clause 6 (tests + re-scan closure) passes. Recipe runs write source files (not just manifests) and are staged for total revert + re-scanned per step. The audit record captures `fix_source` (recipe vs manual). New core principle (recipe-first).
- **ship-vuln-fix** 0.1.0 — vulnerability **remediation** skill (VF1–VF8), the second half of the `ship-vuln-scan` → `ship-vuln-fix` pair. Consumes the scan's findings artifact and is **tiered + evidence-gated**: it auto-applies only mechanical, reversible fixes (minimal dependency bumps, transitive overrides/resolutions) behind a confirmation gate and verifies each by re-scan (same engine + replayed advisory snapshot, target CVE closed + no new vuln in the changed subtree) + build/tests + a clean frozen install; it **advises only** (exact plan, never edits) for breaking/major upgrades, code-level mitigations, and no-fix cases. The apply decision is driven by **evidence** (reviewed changelog, no new install scripts, green tests), never the semver delta; installs run with scripts disabled. Per-fix atomic apply/verify/commit-or-revert with a convergence bound; every auto-apply emits a remediation audit record to `docs/security/vuln-remediation/` (NOT `docs/agent/`). Declares `Edit` (scoped by discipline to lockfile/manifest paths) and never opens a PR/pushes without explicit permission.
- **ship-vuln-scan** 0.1.0 — known-CVE / vulnerability **detection** skill (VS1–VS8) across dependencies (SCA), container images, IaC, and secrets. Hybrid execution: orchestrates real scanners (osv-scanner, trivy, grype, pip-audit, npm/pnpm/yarn audit, checkov, gitleaks, syft) when present and falls back to manual lockfile/advisory analysis otherwise, always recording scan provenance and a `full|degraded|not-scanned` coverage flag so "couldn't scan" is never reported as "clean". Triages by CVSS+EPSS+KEV+reachability and emits a normalized per-surface findings artifact. The `ship-reviewed-prs` SC persona now delegates known-CVE depth here on lockfile/manifest changes. First half of the `ship-vuln-scan` → `ship-vuln-fix` pair (remediation skill planned next). Detect-only — declares `Bash` for scanners but no `Write`/`Edit`.
- **Tool-policy validator check** — `scripts/validate-skills.py` now machine-enforces two trust invariants: the pure-rubric review skills (`ship-clean-code`, `ship-tested-code`, `ship-secure-code`, `ship-devops`) stay read-only (`Read`/`Grep`/`Glob` only), and `ship-vuln-scan` stays detect-only (no `Write`/`Edit`). Tokenizes the `allowed-tools` scalar respecting `Bash(...)` scopes.
- **Migrated all 6 plugins from `ship-it-ops/ship-code`** — booster is now the single marketplace: **ship-clean-code** 1.1.0, **ship-tested-code** 1.1.0, **ship-debugged-code** 1.0.0, **ship-secure-code** 1.0.0, **ship-reviewed-prs** 1.3.1 (with the `/ship-reviewed-prs:review-pr` command), **ship-devops** 0.2.0. Versions carried over unchanged; install with `<plugin>@booster`.
- **PR dogfood workflow** — `.github/workflows/pr-review.yml` (from ship-code) runs ship-reviewed-prs against PRs to this repo. Requires the `CLAUDE_CODE_OAUTH_TOKEN` repo secret.
- **Validator checks ported from ship-code** — plugin file-parity (every skill file must have a plugin symlink; orphans are errors), `${SKILL_DIR}` leakage detection, test-fixture parity, and plugin.json name == directory basename. Plus a `plugin-symlinks` CI job that verifies symlinks survive checkout.
- ship-code's `docs/agent/` knowledge (decisions, patterns, scars, open questions about the migrated skills) merged into booster's `docs/agent/`.
